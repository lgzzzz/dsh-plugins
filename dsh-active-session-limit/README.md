# dsh-active-session-limit

限制同时活跃的会话数（默认 3，含子智能体），新会话错开 5 秒启动。

## 行为

- **名额**：一个会话开始跑任务（提出第一个 step）时占一个名额，跑完转空闲时交回。名额占满后，
  后到的会话按先来先到排队；排队中的会话在界面上保持「运行中」，但不会进入这一步的模型请求。
- **冷却**：只有**新会话**（还没跑过任何回合的会话）要在上一个会话结束满 5 秒后才启动；已有会话
  继续对话只受名额限制。
- **子智能体**：子智能体会话同样占名额、同样按新会话等冷却。名额占满而子会话在等时，它可以临时
  接管正等着它的父会话的名额 —— 否则「父会话等子会话、子会话等名额」会互相卡死。
- **取消**：排队期间被用户停止，等待随即结束，不占名额。
- **可见性**：不往会话记录里写任何提示；排队 / 放行 / 接管的经过只写宿主日志。

## 配置

在 `cordis.patch.yml` 的同名行里改：

| 字段 | 默认 | 含义 |
|---|---|---|
| `maxActive` | `3` | 同时活跃的会话上限，含子智能体 |
| `cooldownMs` | `5000` | 上一个会话结束后，新会话要再等的毫秒数；`0` 只保留名额限制 |

## 已知边界

- 只统计本进程内的智能体；进程外的子智能体提供方（external subagent provider）不经过这里的
  `agent/*` 事件，不计入。
- 排队发生在会话装配完这一 step 的提示词与工具之后、第一个模型请求之前；排队期间的提示词不会
  落进会话记录，进程重启会丢掉还在排队的这一轮。
- 插件激活时已经在跑的会话按「占着名额」接管，等它们转空闲时释放。

更多实现细节、取舍与验证步骤见仓库文档 `docs/dsh-active-session-limit.md`。
