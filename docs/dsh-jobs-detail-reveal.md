# dsh-jobs-detail-reveal

点开「后台任务」里某条命令的输出后，**会话面板自动把这条任务行滚到顶部**：收起它的按钮（也就是
这条行本身）停在面板顶部，命令输出在下面整块露出来；详情在本面板里装不下时，面板的 `max-height`
跟着加高到装得下（不超过视口），关掉详情立刻恢复。纯客户端插件：不改上游产物、不换类名、不写
React 状态，只动面板元素的 `scrollTop` 与内联 `max-height`，从 profile 移除即恢复原样。

-----

## 它做的是什么

| | 行为 |
|---|---|
| 位置 | 会话面板（`[data-session-panel]`）的「后台任务」分区，任务行（`[data-job-row]`）的展开按钮 |
| 触发 | 点某条任务行**展开**命令输出（`aria-expanded` 从 `false` 变成 `true`）；点收起、点停止按钮、点聊天流里的工具卡片都不触发 |
| 滚动 | 把那条行顶到面板内容区顶部（留出面板自己的 6px 上内边距），一次到位；内容不够长、滚不到位时停在上限 |
| 加高 | 行 + 详情 + 面板上下内边距比上游的 `max-height` 还高时，把面板加高到刚好装下；封顶在视口允许的高度（面板顶边之上 12px、底边之下 12px） |
| 恢复 | 收起详情（再点一次行、上游自己收起、行被移除）立即撤掉加高；插件卸载时一并还原 |
| 流式变高 | 运行中的任务还在出字时，详情变高就跟着重算加高，**不重新滚动**——读者滚上去看别的内容不会被拽回来 |
| 不碰的东西 | 上游的类名、样式表、React 状态、展开状态、任务观察流，以及聊天流里工具卡片自己的终端区块 |

-----

## 为什么

会话面板是个浮层：`max-height: calc(100dvh − 输入区高度 − 24px)` + `overflow-y: auto`
（上游 `SessionPanel.module.css`）。面板里的分区依次排下来——环境、OpenCode Go、后台任务……

后台任务的行可以点开命令输出：详情插在行下面，行 + 详情约 340–380px（输出区自己封顶 288px，
再加命令行与提示行）。点开时上游只改 `expanded` 状态，**不碰面板的滚动位置**——`scrollTop` 还停在
原来的地方（一般在顶部）。于是：

- 新插进来的详情落在可视区外面，得自己往下滚才看得到完成的输出；
- 「收起」这件事就是再点一次那条行，而那条行也一起滚出了视野。

所以这里补两件上游没做的事：把行顶到面板顶部（于是收起按钮就在顶部、详情在它下面完整可见），
以及装不下时把面板加高（于是不用在面板里再滚一次）。

-----

## 时序

一次点击要走三段，缺一段都会定位到错的几何：

| 阶段 | 等什么 | 为什么 |
|---|---|---|
| 1. 等状态落定 | 最多 2 帧，看 `aria-expanded` 是否变成 `"true"` | 点按钮只是翻 React 状态，属性要等这次提交之后才变；这一下也可能是「收起」，那就什么都不做 |
| 2. 等详情挂载 | 最多 90 帧（约 1.5 秒） | 详情要等观察流的第一帧输出到达才渲染（上游 `expanded && view !== undefined`）；等不到就放弃，不在后台空转 |
| 3. 加高，然后滚动 | 详情已经在页面上 | 顺序不能反：先滚的话面板还没装下详情，滚动会被内容长度夹住，行到不了顶部 |

认下来之后只挂**一个**尺寸观察者（详情所在的 `<li>`）：详情流式变高、上游收起详情、行被移除都会
让它回调，回调里先复核行与展开状态，再重算加高。窗口尺寸变化另外重算一次（上游的 `max-height`
本身跟视口走）。两者都**不重新滚动**。

-----

## 怎么算的

两个纯函数（[`src/plan.ts`](../dsh-jobs-detail-reveal/src/plan.ts)）：

```text
scrollTop = 行顶 − 面板顶 + 当前 scrollTop − 上边框 − 上内边距     （不小于 0）
需要的高度 = <li> 高度 + 上内边距 + 下内边距
可用的高度 = 视口高度 − 面板顶 − 12
新 max-height = 需要的高度 > 上游 max-height 时取 min(需要的高度, 可用的高度)，否则不动上游
```

- 「详情要占的高度」取 `<li>`：行顶到内容区起点后，行与详情正好把这段空间填满；
- 上游 `max-height` 每次都是**先撤掉自己写的值、重新读计算样式**得到的，所以窗口、断点、上游
  改算式都跟得上，不会把自己上一次加高当成上游默认值叠上去；
- 撤值读值再写值的中间会短暂变矮，浏览器可能顺手夹一次滚动位置，所以写入前后保存 / 还原
  `scrollTop`；
- 只加高到「详情装得下」，不无条件撑满视口：装得下时面板高度与上游完全一致。

`window` 上，会话切换导致面板重挂也不丢。

## 契约与静默失败

`pnpm --filter dsh-jobs-detail-reveal check:css` 在上游改名时显式失败，而不是让行为在页面上静默
失效：

| 失效的上游事实 | 页面上的表现 |
|---|---|
| 面板根不再打 `data-session-panel` | 找不到滚动口，点开详情后仍要自己往下滚 |
| 面板不再是 `overflow-y: auto` 的滚动口 | 改 `scrollTop` 没有效果 |
| 面板的 `max-height` 不再从 `--dsh-conversation-viewport-height` 算起 | 加高的上限算错，可能把面板顶出视口 |
| 任务行不再打 `data-job-row` | 找不到要顶到顶部的行，滚动不触发 |
| 行内展开按钮不再带 `aria-expanded` | 认不出开合，滚动与加高都不触发 |
| 「收起」不再是点这一行（`row.collapseAria` 移走） | 把行顶到顶部失去前提：收起按钮不在行里了 |
| 详情里不再有 `[data-terminal]` | 认不出详情是否挂载，等待循环到点放弃 |

## 挂载与验证

```powershell
pnpm --filter dsh-jobs-detail-reveal build
pnpm --filter dsh-jobs-detail-reveal typecheck
pnpm --filter dsh-jobs-detail-reveal test        # 纯计算 / 锚点识别 / 完整时序（替身 window）
pnpm --filter dsh-jobs-detail-reveal check:css   # 上游契约（8 条）
```

仓库存放与挂载：

```powershell
./add-plugins.ps1                     # 仓库里所有带 dsh.bundle 的 dsh-* 目录一起挂
```


挂载后不需要重启 `dsh web`：profile 开着 HMR，已打开的页面会收到客户端插件图更新。要确认行为，
在会话面板里点开一条**已有输出**的后台任务行：

1. 那条行应停在面板顶部（面板上方的分区随之滚出视野），收起它的按钮就在顶部；
2. 详情整体可见；详情比面板默认限高还高时，面板变高（在视口以内），不再需要面板内滚动；
3. 再点一次那条行：详情收起，面板恢复原来的高度，滚动位置不动。

## 已知边界

- **只在打开的那一下滚动**：之后详情流式变高、窗口尺寸变化只重算高度，不改滚动位置——读者的
  阅读位置优先。
- **视口实在太小就不加高到「装下」**：可用高度 = 视口 − 面板顶 − 12px，加高封顶在这里；面板在
  可停靠时本来就在主对话右侧，窄窗口下会变成 280px 宽的浮层，输出区自己还有 288px 的滚动上限，
  极矮的窗口里仍然可能要在面板里再滚。
- **收起不做反向滚动**：详情收起后不把面板滚回原来的位置。上游本来就没有这个动作，读者随时可以
  自己滚。
- **不接管「已结束」列表的折叠 / 清空**：那些操作让详情消失时，尺寸观察者会撤掉加高。
- **与其它面板插件无耦合**：`dsh-ui-css-patches` 固定面板宽度、`dsh-opencode-status` 增加分区，
  都只是改变面板内容，本插件按实测几何计算，不需要知道它们的存在。
- **多装一次不会叠加**：后装的那一个会覆盖先装的 `max-height`；正常通过 profile 挂载只装一次。
