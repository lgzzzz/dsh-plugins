# 2. 工作原理与失败模式

本册说清插件认哪几条 DOM 信号、修正量怎么算、时序落在哪一步，以及每条失败路径的结果。读完能判断一次「没补上」是配置问题、上游改形状，还是本来就该让它去。

-----

## 四条 DOM 信号

滚动口、锚点行、折叠进行中、尾随输出，各对应一条上游契约：

| 信号 | 选择器 / 属性 | 用途 |
|---|---|---|
| 折叠窗口 | 滚动口内联 `overflow-anchor: none` | 动画折叠的时间窗：变成 `none` 时记锚点，写回 `""` 时收尾 |
| 即时折叠 | 列表子树的 `hidden` 属性（从无到有） | 不带画折叠的一次性布局变化 |
| 滚动口与流程列 | `[data-chat-turn-spacer]`（含它前面的兄弟节点） | 占位元素反查列表、滚动口（`closest('[data-conversation-scroll]')`）与流程列 |
| 锚点行 | `[data-chat-anchor-key]` + `[hidden]` + `[data-chat-motion="collapse"]` + 本批批元素 | 取阅读线上第一条稳定的行；折叠中的行、子树里有折叠元素的行，以及**本批马上要隐藏的元素**（自身是批元素，或子树里含批元素）都跳过 |

滚动口取法与 ui-chat 自己的 `viewport.attach` 一致：占位元素的列表再往上找 `[data-conversation-scroll]`，找不到就用列表本身（共享滚动模式与普通模式各命中一条）。列表随会话挂载/卸载，运行时用 `childList` 观察**限频**重扫（500ms），并回收已断开的滚动口。

-----

## 修正量怎么算

两个入口共用同一个记账方式：记下锚点行相对滚动口顶边的偏移，之后每次重新测量，**差值就是本次要写的滚动量**（`scrollTop += 测量值 − 参照值`）。

- 锚点不动（折叠在阅读线下方）时差值为 0，不写。
- 差值小于 `MIN_DELTA`（0.5px）按亚像素抖动处理，不写。
- 折叠把内容整体上移 `H` 时差值为 `−H`，滚动位置减少 `H`，锚点回到原处。

即时折叠没有「折叠前的参照值」可用，于是把本批刚被隐藏的元素临时改回可见、强制一次布局量出参照值，再按原值写回 `hidden`、再量一次——两次之差就是要补的量。这一对测量同时也是与浏览器原生锚定的分工：**原生锚定如果已经自己补过，第二次测量读到的就是补过的位置，差值为 0，插件不重复写。**

这一对测量给选锚点加了一条硬约束：**本批正在被隐藏的元素不能当锚点。** 它们在「临时改回可见」的那一步看起来完全可用——阅读线上的过程组根尤其像——但紧接着又会被隐藏，第二次测量时已经测不到，整次补偿就此放弃。所以 `pick()` 排除的是整批元素，以及**子树里含批元素的那些行**（过程组根正是这种：自己带锚点键，批元素是它的后代）。

-----

## 时序落在哪一步

- 动画折叠：`ResizeObserver` 的回调发生在布局之后、绘制之前——正是原生滚动锚定补位置的那一步；每次布局变化（动画的每一帧）补一次，窗口关闭时再补最后一次（尾随输出时跳过这最后一次）。
- 即时折叠：`MutationObserver` 回调是属性变化后的微任务，仍在同一帧的绘制之前；插件在这段同步代码里量完两次几何并写回滚动位置，因此这一帧画出来就是补过的位置。

实测（headless Chrome）：即时折叠的锚点位移是 0px（一次到位）；动画折叠的**终值**是 +2px，但动画进行中仍会出现瞬时残差——382px 的折叠峰值约 126px。原因是动画的中间帧由 ui-chat 的 `height` 过渡驱动：过渡值在布局回调之前已经推进，插件只能在布局回调里追，追不上当前帧的进度。这条边界见下。

## 失败路径

| 情况 | 结果 |
|---|---|
| 页面里没有 `[data-chat-turn-spacer]`（聊天视图没挂载） | 不装任何观察，静默 no-op；发现是新会话挂载时按限频重扫补上 |
| 阅读线上没有可用锚点行 | 本次什么都不写（降级为空操作） |
| 阅读线上只剩本批马上要隐藏的行 | 同样降级为空操作（不回退到它们，回退会因第二次测量失效而放弃） |
| 锚点行中被折叠掉、卸载或清空 | 结束本次会话，位置交回 ui-chat 自己的策略 |
| 上游不再写内联 `overflow-anchor`，或改了 `data-chat-*` | 补丁静默失效；`pnpm check:css` 里的 7 条契约会显式失败，提示里写明后果 |
| 没有 DOM 的环境（宿主侧装配客户端半部） | `apply` 直接返回，不抛错 |
| 浏览器不支持 `ResizeObserver` | `apply` 不装（现代浏览器都支持；本插件按布局回调补，没有它就退化成不补） |

-----

## 已知边界

- **动画中间帧的残差。** 动画折叠的落点与折叠前一致（实测 +2px），但过渡进行中的画面仍可能有不到一帧的位移；要消掉它只能改 ui-chat 自己的动画，超出本插件「只补滚动位置」的范围。
- **展开不回补。** 只认 `hidden` 从无到有。
- **React 直接卸载行时不补。** 没有 `hidden` 属性可认。
- **`hidden` 的取值原样写回。** 即时折叠期间临时显回元素，再按属性当时的取值（通常是 `until-found`）写回，不改值、不改 React 的状态。
