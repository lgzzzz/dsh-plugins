# 2. 工作原理与失败模式

> 本文件是 [dsh-ui-chat-fold-anchor 说明](../dsh-ui-chat-fold-anchor.md) 的第 2 册：滚动口与阅读线的定义、两条 DOM 信号、修正量与时序、逐条失败路径与已知边界。

本册先说清**滚动口**与**阅读线**这两个贯穿全文的概念，再说插件认哪几条 DOM 信号、修正量怎么算、时序落在哪一步，以及每条失败路径的结果。读完能判断一次「没补上」是配置问题、上游改形状，还是本来就该让它去。

-----

## 滚动口是什么

**滚动口是承载聊天、真正发生滚动的那个元素**：插件读写的 `scrollTop`、所有几何测量用的参照边（`getBoundingClientRect().top`）、以及观察 `hidden` 折叠信号的根，都落在它身上。它就是会话根上的外层滚动口 `[data-conversation-scroll]`——ui-chat 自己的 `viewport.attach` 取的也是同一个元素。

发现方式因此是**直接枚举**：`document.querySelectorAll('[data-conversation-scroll]')`，一个滚动口挂一个补偿器。这是「只支持共享滚动模式」省下来的那一步——上游在找不到外层滚动口时会把列表本身当滚动口，本插件不认那条布局：枚举不到滚动口就什么都不装，所以既不需要先找聊天列表、也不需要列表尾部的占位元素 `[data-chat-turn-spacer]`。

滚动口随会话挂载 / 卸载，所以运行时用 `childList` 观察 `document.body` 子树、**限频 500ms** 重扫一遍，并回收已经断开（`isConnected === false`）的滚动口。

插件对上游的依赖也因此收窄到三条：折叠写下的 `hidden="until-found"`、滚动口 `[data-conversation-scroll]`、锚点行 `[data-chat-anchor-key]`。列表与占位元素改名、换位置都不影响它。

绑定也更稳：观察根是滚动口而不是列表，所以列表在同一个滚动口里被 React 替换（切会话）时不必重挂观察；只有滚动口自己被卸载时才回收。

-----

## 阅读线是什么

**阅读线是滚动口顶边下方 1px 处的一条水平参考线**，即可见区域的上沿再往里 1px。代码里就是参照边加 1px：

```js
const scrollerTop = scroller.getBoundingClientRect().top
// 锚点行必须满足：rect.bottom > scrollerTop + READING_LINE_OFFSET   （READING_LINE_OFFSET = 1）
```

这 1px 让阅读线落在滚动口**内部**，而不是压在边界上；取法与 ui-chat `capturePosition()` 的取样位置相同（它按 `viewport.top + 1` 取可见内容），所以插件认的「第一行」和 ui-chat 存位置时认的是同一行。

两条容易与它混淆的线：

- ui-chat 选**活跃轮次**用的是另一条线：滚动口顶边 + `min(96px, 视口高 × 20%)`（`readVisibleTurn`），位置比阅读线更靠下。上游文档里说的「阅读线」指的是这一条，与本插件说的不是同一条。
- 阅读线不参与修正量的计算：它只用来决定锚点行是哪一条。

### 锚点行怎么选

锚点行是本次补偿的参照物：一条带 `data-chat-anchor-key`、折叠前后都能重新找到的行。插件在**滚动口子树**里按 DOM 顺序遍历所有带该键的行，第一条同时满足下面全部条件的行就是锚点行：

1. 没有被隐藏——自己或任意祖先带 `[hidden]` 都算（`row.closest('[hidden]')`）；
2. 不属于**本批**正在被折叠的元素，也不是它们的祖先或后代；
3. 有稳定键，且高度不为 0；
4. **底边越过阅读线**（`rect.bottom > 滚动口顶边 + 1px`）。

于是锚点落在**压在阅读线上（或紧接其下）的那条行**：它上方的行已经整个滚出视口（底边在阅读线以上），会被条件 4 跳过。选中后只记两件事——`key`（行的 `data-chat-anchor-key`，第二次测量按它找回同一行）与 `top`（行顶边相对滚动口顶边的偏移，`rect.top − 滚动口顶边`）。一条可用的行都没有时 `pick()` 返回 `null`，本次什么都不写。

```
        （上方：已滚出视口的行，不参与选取）
滚动口顶边 ══════════════════════════════════
阅读线 ───── 顶边 + 1px ────────────────────
  锚点行：DOM 顺序上第一条底边越过阅读线的行     ← 记下它的 key 与 top
    └ 本批被隐藏的元素（可能就在锚点行的子树里，如过程组的折叠体）→ 条件 2 整批排除
  以下各行                                   ← 折叠在阅读线下方时它们不动 → 差值 0，不写
滚动口底边 ══════════════════════════════════
```

条件 2 是这次选取里唯一不直观的一条：补偿的第一步会把本批元素临时显回，它们在那一刻看起来完全可用，但紧接着又会被隐藏。**拿本批元素当锚点，第二次测量就测不到它**，整次补偿随之放弃（原因见「修正量怎么算」）。

## 两条 DOM 信号

折叠与锚点行各对应一条上游契约：

| 信号 | 选择器 / 属性 | 用途 |
|---|---|---|
| 折叠 | `hidden` 属性（从无到有） | ui-chat 收起行的那一次布局变化 |
| 锚点行 | `[data-chat-anchor-key]` + `[hidden]` + 本批元素 | 按「锚点行怎么选」一节的规则取阅读线上的第一条稳定行 |

两条信号的作用域是同一个元素——滚动口 `[data-conversation-scroll]`：它既是 `hidden` 的观察根，也是锚点行的查找根。

观察根放大到整个滚动口子树（含会话输入区）是安全的：客户端产物里会写 `hidden` 属性的只有 ui-chat 的两处——收起行用的 `useSearchableHidden`（取值 `until-found`）与过程组 header 的 `useMotionHidden`（空值），两者都在聊天列内，所以「谁被隐藏」这个信号集并没有变大。

-----

## 修正量怎么算

折叠没有「折叠前的参照值」可用，于是把本批刚被隐藏的元素临时改回可见、强制一次布局量出参照值，再按原值写回 `hidden`、再量一次——两次之差就是要补的量（`scrollTop += 测量值 − 参照值`）。

- 锚点不动（折叠在阅读线下方）时差值为 0，不写。
- 差值小于 `MIN_DELTA`（0.5px）按亚像素抖动处理，不写。
- 折叠把内容整体上移 `H` 时差值为 `−H`，滚动位置减少 `H`，锚点回到原处。

这一对测量同时也是与浏览器原生锚定的分工：**原生锚定如果已经自己补过，第二次测量读到的就是补过的位置，差值为 0，插件不重复写。**

它还带来一条硬约束：**本批正在被隐藏的元素不能当锚点。** 它们在「临时改回可见」的那一步看起来完全可用——阅读线上的过程组根尤其像——但紧接着又会被隐藏，第二次测量时已经测不到，整次补偿就此放弃。所以 `pick()` 排除的是整批元素，以及**子树里含批元素的那些行**（过程组根正是这种：自己带锚点键，批元素是它的后代）。

记账与 DOM 的分工：`fold-anchor.ts` 只管参照点、修正量与失效判定，全部 DOM 读写收在 `viewport.ts` 的 `HiddenBatchProbe` 后面——所以前者能在假探针上直接测，不必摆 DOM。

## 时序落在哪一步

`MutationObserver` 回调是属性变化后的微任务，仍在同一帧的绘制之前；插件在这段同步代码里量完两次几何并写回滚动位置，因此这一帧画出来就是补过的位置。

实测（headless Chrome）：即时折叠的锚点位移是 0px，一次到位。

## 失败路径

| 情况 | 结果 |
|---|---|
| 页面里没有 `[data-conversation-scroll]`（会话视图没挂载，或布局不是共享滚动模式） | 不装任何观察，静默 no-op；发现是新会话挂载时按限频重扫补上 |
| 阅读线上没有可用锚点行 | 本次什么都不写（降级为空操作） |
| 阅读线上只剩本批马上要隐藏的行 | 同样降级为空操作（不回退到它们，回退会因第二次测量失效而放弃） |
| 锚点行被折叠、卸载或清空 | 本次什么都不写（`measure()` 返回 null） |
| 上游改用卸载节点收起行，或改了 `data-chat-*` | 补丁静默失效；`pnpm check:css` 里的 3 条契约会显式失败，提示里写明后果 |
| 没有 DOM 的环境（宿主侧装配客户端半部） | `apply` 直接返回，不抛错 |

-----

## 已知边界

- **只支持共享滚动模式。** 滚动口按 `[data-conversation-scroll]` 直接枚举；没有这个元素的布局（列表自己滚）不装观察，本条路径上阅读位置仍会被顶走。
- **折叠动画不在补偿范围内。** 设置里把「工作步骤收起时机」切成「下次有新消息时」后，ui-chat 用内联 `overflow-anchor: none` + 高度过渡收起过程组；那段时间原生锚定正是被它自己关掉的那个，而本插件只认写在行上的 `hidden`，因此这条路径的阅读位置仍会被顶走。
- **React 直接卸载行时不补。** 没有 `hidden` 属性可认。
- **展开不回补。** 只认 `hidden` 从无到有。
- **`hidden` 的取值原样写回。** 补偿期间临时显回元素，再按属性当时的取值（通常是 `until-found`）写回，不改值、不改 React 的状态。
