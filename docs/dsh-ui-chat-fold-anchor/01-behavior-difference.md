# 1. 行为差异与影响面

> 本文件是 [dsh-ui-chat-fold-anchor 说明](../dsh-ui-chat-fold-anchor.md) 的第 1 册：装与不装各看到什么、这条折叠路径缺什么、哪些折叠不需要补。

本册说清装与不装各看到什么、这条折叠路径缺什么，以及哪些折叠本来就不需要补。读完能判断一次页面上的「跳动」该不该由这个插件负责；文中**滚动口**、**阅读线**、**锚点行**、**本批元素**这些词的含义见[第 4 册术语表](04-glossary.md)。

-----

## 装与不装各看到什么

不装插件时，一次发生在阅读线上方的折叠会把正在看的内容整体上移**被折叠掉的高度**；折叠量大时这段内容直接移出视口。装插件后同样的折叠里，阅读线上的锚点行停在原位置，上方少掉的空间由更早的内容补进来。

实测（headless Chrome，`test/browser/`，一个 382px 高的过程组在阅读线上方折叠）：

| 场景 | 不装插件 | 装插件 |
|---|---|---|
| 即时折叠，滚动口没有原生锚定 | 锚点位移 **−380px** | **0px** |
| 即时折叠，滚动口有原生锚定 | **0px**（浏览器自己补） | **0px**（不重复补） |

「装插件」的一行数字说明插件只补该补的：浏览器已经补过的情形，插件的两次测量读到的是补过的位置，差值为 0，于是不写。

-----

## 这条折叠路径缺什么

ui-chat 收起过程组时不带任何滚动位置补偿：只给行加上 `hidden`（取值 `until-found`），布局一次到位，位置交给浏览器的原生滚动锚定（上方内容变矮时由浏览器自己维持阅读位置的能力，受 CSS `overflow-anchor` 控制）。浏览器不支持它（Safari）或它被关掉（滚动口上写着 `overflow-anchor: none`）时，折叠掉的高度就没人补——**缺的就是这一段**。插件在折叠发生的同一帧里补回来：属性变化的微任务里连续量两次几何并写回滚动位置。

-----

## 哪些折叠不需要补

- **折叠发生在阅读线下方。** 锚点行的视觉位置不变，修正量算出来是 0，插件不写滚动位置，ui-chat 想做的「下面那段收上去」照旧。
- **阅读线上只剩本批马上要隐藏的行。** 这类行在补偿的第一次测量里看起来可用，第二次测量时已经测不到；拿它们当锚点会让整次补偿失效，所以插件直接跳过它们——阅读线上再没有别的行可锚时，本次什么都不写。
- **两次测量之间锚点行消失。** 被折叠、卸载或清空时 `measure()` 返回 null，本次什么都不写。
- **行是被 React 直接卸载的。** 没有 `hidden` 属性可认，插件不动——这条路径没有可依赖的信号。
- **展开。** 只认 `hidden` 从无到有；把折叠段展开是用户自己的动作，改的是内容高度而不是折叠，插件不回补。

-----

## 上游可用的扩展面

ui-chat 的聊天视图暴露了一个「Verbose 折叠」用的策略注入面（见 [dsh-ui-chat-verbose-fold](../dsh-ui-chat-verbose-fold.md)），但它只改「折什么」，没有任何滚动位置相关的开关；滚动策略（`ChatViewport` 的 `capturePosition` / `preserve`）是组件内部对象，插件拿不到。因此本插件走 DOM 这一层：只读折叠留下的信号与行的几何，只写滚动口的 `scrollTop`，不改 ui-chat 的状态、不注册槽位、不遮蔽任何组件。

代价是它依赖 ui-chat 的内部形状——`hidden="until-found"` 的写法与两个 `data-chat-*` 锚点（会话滚动口、锚点行）。这些都在 `contract.json` 里逐条钉住：上游改名或换机制时 `pnpm check:css` 显式失败，而不是让补丁在页面上静默失效。
