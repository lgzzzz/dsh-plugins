# 1. 行为差异与影响面

本册说清装与不装各看到什么、两条折叠路径各自缺什么，以及哪些折叠本来就不需要补。读完能判断一次页面上的「跳动」该不该由这个插件负责。

-----

## 装与不装各看到什么

不装插件时，一次发生在阅读线上方的折叠会把正在看的内容整体上移**被折叠掉的高度**；折叠量大时这段内容直接移出视口。装插件后同样的折叠里，阅读线上的锚点行停在原位置，上方少掉的空间由更早的内容补进来。

实测（headless Chrome，`test/browser/`，一个 382px 高的过程组在阅读线上方折叠）：

| 场景 | 不装插件 | 装插件 |
|---|---|---|
| 折叠动画（`collapse` + `overflow-anchor: none`） | 锚点位移 **−380px** | **+2px** |
| 即时折叠，滚动口没有原生锚定 | 锚点位移 **−380px** | **0px** |
| 即时折叠，滚动口有原生锚定 | **0px**（浏览器自己补） | **0px**（不重复补） |

「装插件」的两行数字说明插件只补该补的：浏览器已经补过的路径，插件的两次测量读到的是补过的位置，差值为 0，于是不写。

-----

## 两条折叠路径各自缺什么

ui-chat 的折叠由两条路径完成，本插件各认一条信号。

**折叠动画。** `createFlowMotion.collapse` 在动画开始时把滚动口的原生滚动锚定关掉（内联 `overflow-anchor: none`），动画结束再写回。关掉的原意是让「折叠掉的空间向下收、上方内容不动」由它自己算，但这段窗口里没有任何人补阅读位置：折叠掉的高度在阅读线上方时，阅读线就跟着上移。**这条路径在任何浏览器上都缺补偿**——原生锚定正是被关掉的那个。

**即时折叠。** 不开折叠动画时，ui-chat 只给行加上 `hidden`（取值 `until-found`），布局一次到位。这条路径自己不做什么，位置交给浏览器的原生滚动锚定；浏览器不支持 `overflow-anchor`（Safari）或该能力被关掉时，就没有人补。

两条路径的共同点是：**都由本插件在折叠发生的同一帧里补回来**——动画路径跟着 `ResizeObserver` 的布局回调走，即时路径在属性变化的微任务里连续量两次几何。

-----

## 哪些折叠不需要补

- **折叠发生在阅读线下方。** 锚点行的视觉位置不变，修正量算出来是 0，插件不写滚动位置，ui-chat 想做的「下面那段收上去」照旧。
- **阅读线上只剩本批马上要隐藏的行。** 这类行在补偿的第一次测量里看起来可用，第二次测量时已经测不到；拿它们当锚点会让整次补偿失效，所以插件直接跳过它们——阅读线上再没有别的行可锚时，本次什么都不写。
- **行是被 React 直接卸载的。** 没有 `hidden` 属性可认，插件不动——这条路径没有可依赖的信号。
- **展开。** 只认 `hidden` 从无到有；把折叠段展开是用户自己的动作，改的是内容高度而不是折叠，插件不回补。
- **折叠段就是正在看的那一段。** 锚点行被折叠掉时插件结束会话——那段内容本来就要消失，位置交回 ui-chat 自己的策略。
- **尾随输出（跟随到底部）。** 动画窗口内的修正照做，但折叠收尾那一次让位：ui-chat 会在折叠结束时平滑回到底部，插件再补一次会把它拽回来。

-----

## 上游可用的扩展面

ui-chat 的聊天视图暴露了一个「Verbose 折叠」用的策略注入面（见 [dsh-ui-chat-verbose-fold](../dsh-ui-chat-verbose-fold.md)），但它只改「折什么」，没有任何滚动位置相关的开关；滚动策略（`ChatViewport` 的 `capturePosition` / `preserve`）是组件内部对象，插件拿不到。因此本插件走 DOM 这一层：只读折叠留下的信号与行的几何，只写滚动口的 `scrollTop`，不改 ui-chat 的状态、不注册槽位、不遮蔽任何组件。

代价是它依赖 ui-chat 的内部形状——内联 `overflow-anchor` 的写法、`data-chat-*` 锚点、`[data-chat-turn-spacer]` 的位置。这些都在 `contract.json` 里逐条钉住：上游改名或换机制时 `pnpm check:css` 显式失败，而不是让补丁在页面上静默失效。
