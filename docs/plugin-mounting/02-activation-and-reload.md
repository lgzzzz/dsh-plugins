# 生效与重载

> 本文件是 [插件挂载、卸载与生效](../plugin-mounting.md) 的第 2 册：宿主与浏览器各自怎样应用一次挂载、卸载或代码变更，以及哪些情况仍然必须重启进程或刷新页面。

-----

## 1. 宿主端：一次重组合

web profile 的 HMR 监听 profile 的 `package.json`、两份用户 patch 与每个 `--patch` 覆盖文件。文件变化或管理操作到来时，它按顺序做四件事：

1. 重新读取 bundle 层与 patch，组合出完整的 Loader 条目列表；
2. 停掉不再列出的行，等它们的异步清理完成；
3. 重新发布安装映射，启动新增或变化的行；
4. 对已加载的模块做文件比较：profile 目录与 `link:` 包的目标目录都在比较范围内，变化且可替换的模块被逐出并重新导入。

因此：

- **挂载**后新行启动，宿主半部的工具、服务与监听在后续请求里可用；已打开的会话不需要重启。
- **关闭**后 fiber 卸载、服务撤回，依赖它的插件级联重载；再次打开会重新执行它的 `apply`，进程内状态从零开始。
- **移除**先停行，再 `pnpm remove`，最后重组合并逐出被删除映射的模块。不同版本的更新因此要先卸载再安装。
- 每次操作的结果以 `application` 为准（取值见[第 1 册](01-mount-and-unmount.md)第 3 节的表）；`restart-required` 会带 `restartReason` 说明为什么当前进程不应用。

-----

## 2. 浏览器端：跟随客户端图

客户端插件行来自宿主已激活条目的 `dsh.client` 声明。宿主在客户端产物一侧组合整张图；已打开的页面通过 `client-hmr` 的 `pluginEvents/follow` 流接收它：

- 每一代流先发 `baseline`（当前完整图，每行带该插件的同步 Config），之后发 `graph`（行的增删、rev 变化）与 `rebuilt`（产物重建）增量；
- 新增一行：页面按带 revision 的单资源地址取回 bundle、物化并挂载；
- 删除一行：卸载 fiber，等异步清理完成后回收它独占的模块与 `<style>`；仍被其他活动行使用的共享模块保留；
- 被替换的插件用全新 fiber 与全新组件重新挂载，插件内的 React 状态丢失；会话、工作区与连接状态不受影响；
- 依赖被替换插件的行会随 Cordis 的服务级联一起重载。

这些都不需要刷新页面。页面只应用与自身启动时同 release（DSH 版本与构建 commit）的图与重建帧；Host 换成另一个 release 时，页面继续运行旧插件，直到刷新。

-----

## 3. 改代码后怎样生效

### 浏览器半部（`lib/client.js`）

```bash
pnpm --filter <包名> build
```

宿主按每个客户端产物的 mtime、ctime 与大小轮询（`client-hmr`，默认 500ms）；文件变化后它发布新的 rev，页面替换该插件——约半秒内开始，无需刷新或重启。构建工具必须**改写入口产物本身**：DSH 官方的客户端构建预设会在所有 chunk 写完后重新标记入口，本仓库的 [tsdown.client.mjs](../../tsdown.client.mjs) 没有这一步，只有 chunk 变化、`lib/client.js` 未变化时可能检测不到。

### 宿主半部（`index.ts` / `src/`）

HMR 默认 `root: []`，**不监视模块源码**；已加载的源码改动只在下一次重组合时与磁盘比较并替换。触发重组合的方式：

- 在**设置 → 插件**里把本插件关掉再打开（或对任意条目做一次管理操作）；
- 编辑 profile 的 `cordis.patch.yml`（HMR 的配置监视会重组合）。

配置页里保存插件 Config 只应用配置，不会替换已加载的模块，不能用它触发代码更新。想让保存就重载，需要给 profile 的 `hmr` 行配置非空的 `root`（指向本仓库），这属于 profile 级配置：HMR 插件本身会重载并重新建立文件基线。

只改插件自己的 `package.json`（新增或删除 `dsh.client`、改 `exports` / `main`）不在监视范围内，最稳妥是重启 `dsh web`。

## 4. 仍然需要重启进程

| 情况 | 为什么当前进程不应用 |
|---|---|
| profile 没有启用 HMR（headless / SDK / ACP 默认关闭，web 默认开启） | 结果是 `restart-required`，原因为 `no-hmr` |
| 改动落到 DSH 自身静态导入的模块或框架依赖 | `host-module` |
| 保留的安装映射移动到另一个目录，或安装映射 / 本地覆盖发生变化 | `package-moved` |
| 插件运行在 Loader 可遍历条目之外（如程序里直接创建条目） | `unmanaged-plugin` |
| 模块缓存无法与磁盘比较（比较或缓存检查失败） | `module-comparison` |
| 部署使用没有 Node 模块缓存的 packed worker loader | 它没有可替换的模块缓存，代码替换只能重启 |
| 只改了插件 `package.json` 里的声明 | HMR 不监视这个文件；下一次重组合或重启才读到 |

Agent 预设里的行不归插件页管理：插件页对预设行只读，改预设要重新挂载会话。

-----

## 5. 仍然需要刷新页面

- **Host 换了 release**：DSH 升级后，已打开的页面仍在旧 release 上，图与重建帧被忽略，必须刷新。
- **HMR 传输失效**：`client-hmr` 运行在 Connection 与 API Gateway Client 面之上；这两者被替换而新实现激活失败时，页面收不到插件变化，直到刷新。

除此之外，页面断线重连会收到新的 `baseline`，期间漏掉的帧由它覆盖。

-----

## 6. 失败之后

- **浏览器替换失败**：旧 fiber 已卸载，新 bundle 导入或激活失败不会回滚；页面显示该插件的同步错误，并提供不改变 Host 启用状态的重试。无关插件继续运行。
- **宿主激活失败**：操作返回 `failed` 与诊断；该条目不运行，后续每次重组合都会重新导入它，文件或依赖修好后即可恢复。
- **卸载恢复**（如 `dsh-changes-behavior` 对上游产物的补丁）：卸载钩子把文件恢复原样后，客户端产物的轮询会发布新的 rev，已打开的页面随之换回原版，不需要刷新。

-----

## 7. 一览

| 操作 | 重启 `dsh web` | 刷新页面 |
|---|---|---|
| 挂载 / 关闭 / 移除组合包或行（设置 → 插件、`plugin_manager`） | 否 | 否 |
| 重建客户端 `lib/client.js` | 否 | 否 |
| 改宿主半部代码 | 否，但要在下一次重组合时生效 | 否 |
| 改 profile 的 patch / 包清单 | 否 | 否 |
| 改插件 `package.json` 的声明 | 是 | — |
| DSH 升级到另一个 release | 按安装方式重启进程 | 是 |
| profile 未启用 HMR | 是 | — |
