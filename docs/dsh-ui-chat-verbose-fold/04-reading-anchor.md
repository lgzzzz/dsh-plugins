# 阅读位置：收起时如何不顶走内容

> 本文件是 [dsh-ui-chat-verbose-fold 说明](../dsh-ui-chat-verbose-fold.md) 的第 4 册：即时折叠为什么会让内容上跳、补偿如何用两次几何测量守住阅读位置、没有可见锚点时如何回退，以及哪些路径故意不补。

本册说明滚动补偿的边界：读者在流式输出时向上滚开、没有跟底，随后这一轮结束、过程行收起，正在读的那段内容仍停在视口中的原位置；没有可见锚点时（常见于视口被折叠段占满），回退到最后一条用户消息，把它的顶边对齐到阅读线下方。补偿只写滚动口的 `scrollTop`，不改 ui-chat 的状态、不注册槽位、不改变折叠策略；跟底、动画折叠、没有共享滚动口时降级为空操作，没有可见锚点时改走用户消息回退，连用户消息也没有时才不写。读完能判断一次跳动该不该由本插件负责，以及上游形状变化时补偿为什么会显式失败。

-----

## 即时折叠为什么会顶走内容

「回答结束后」的收起路径不带动画：`ChatView` 的 `deferCompletedTurns` 为 `false`，流程列上没有 `data-chat-motion`；`useSearchableHidden` 在 layout effect 里直接给过程行写 `hidden="until-found"`，布局一次到位。ui-chat 自带的 `foldDriver` 只在动画折叠（「下次有新消息时」）时运行，这条即时路径完全交给浏览器的原生滚动锚定。

原生锚定会选择视口内的一条可见节点作为参照。问题出在参照点可能正是本批要隐藏的过程行：它随折叠一起消失后，浏览器对这一次布局变化没有可用的锚点，锚定不生效，阅读线上方被收掉的高度当场消失，视口内容整体上移。过程行越多、收起高度越大，位移越明显。

即使浏览器没有把锚点选进本批，滚动范围也可能在折叠后缩短；只要读者不是贴底，这部分缩短要么由原生锚定补回，要么需要插件补回。补偿把两种情况统一成一次几何差写回。

-----

## 概念

**滚动口**是承载聊天、真正发生滚动的元素：`[data-conversation-scroll]`。本插件读写的 `scrollTop`、所有几何测量的参照边、`hidden` 的观察根与锚点行的查找根都落在它身上。当前 GUI 使用共享滚动模式：这个滚动口包含整个对话面板，聊天列表自己不滚。

**阅读线**是滚动口顶边下方 1px 的水平参考线。1px 让参考线落在滚动口内部而不是压在边界上；取法与 ui-chat `capturePosition()` 的取样位置相同。

**视口**是滚动口当前可见的内容区域：上边界是滚动口顶边，下边界是滚动口顶边 + `clientHeight`。锚点行必须与这段区域相交，才有“被保持的可见内容”可言；回退落点不受这条限制，它本来就是为了把视口带回用户消息。

**锚点行**是阅读线上第一条带 `data-chat-anchor-key`、未被隐藏、且不属于本批的流程行，并且必须与滚动口视口相交（至少露出一部分）。它必须在折叠前后都能按同一个键重新找到，所以补偿期间被临时显回的本批元素全部排除——否则第二次测量会找不到它，整次补偿放弃。首条幸存行完全落在视口下方时不算锚点。

**回退落点**是没有可用锚点时的确定性替代：最后一条带 `data-chat-flow-kind="user"`、未被隐藏且高度非 0 的用户消息行。补偿把它的顶边对齐到阅读线（滚动口顶边 + 1px），让读者回到最后一条用户输入的起点，而不是停在折叠段中间的任意位置。没有这样的用户消息时才真正不写滚动位置。

**本批元素**是一组在同一批 `hidden` 属性变化里被隐藏的元素。即时折叠可能同时隐藏过程组成员、过程组根和嵌套折叠体，所以批次按多条 MutationRecord 聚合，而不是只取第一条。

**原生滚动锚定**是浏览器在上方内容变高/变矮时自动调整滚动位置、保持可见内容不动的能力。补偿不假设它一定可用：可用时两次测量的差值为 0，插件不写；不可用时差值就是需要补的像素。

-----

## 补偿算法

折叠发生时，`FoldAnchorViewport` 在属性变化的微任务里执行以下步骤：

1. 断开自己的 `hidden` 观察，避免接下来的显回/隐藏被当成新批次。
2. 把本批元素的 `hidden` 全部移除，并逐个记入 `folded` 集合；强制一次布局。
3. 按阅读线取一条与视口相交的锚点行。找到时记下它的键与相对滚动口顶边的偏移 `before`，继续第 4 步；找不到时跳到第 5 步。
4. **有锚点**：按原值把 `hidden` 写回本批元素，再强制一次布局；按同一个键重测锚点行，得到 `after`；`delta = after − before`。`|delta| < 0.5px` 视为亚像素抖动不写，否则 `scrollTop += delta`。
5. **没有锚点**：按原值把 `hidden` 写回本批元素，再强制一次布局；从后往前找最后一条未隐藏、高度非 0 的 `[data-chat-flow-kind="user"]` 行，把它的顶边对到阅读线：`delta = userTop − scrollerTop − 1`。`|delta| < 0.5px` 时不写，否则 `scrollTop += delta`；没有可用的用户消息时本次不写。
6. 清空 `folded`，重新挂回 `hidden` 观察。

锚点路径的修正量符号由几何决定：折叠把内容整体上移时 `delta` 为负，滚动位置减少同样的量，锚点回到原处；内容下移时为正。折叠发生在阅读线下方时锚点不动，修正量为 0，插件不写，下方内容照旧收上去。

本批元素及其祖先/后代在选锚点时整批排除。这一条是补偿成立的前提：过程组根自己带锚点键，而它内部的折叠体也在本批里；只排除第一个元素会让锚点落在马上又要隐藏的行上，第二次测量失败，整次补偿被放弃。

锚点还必须与视口相交。整屏都是本批即将收起的行时，首条幸存行落在视口下方；这时不再钉住视口外的行（那等于把视口往回滚一整段折叠高度），而是回退到最后一条用户消息，把它的顶边放到阅读线下方。只有部分露出视口底边的行仍算可用锚点，照常走锚点补偿。

回退路径也以折叠后的几何为准：先复原 `hidden` 并强制布局，再测量用户消息和阅读线的差，所以写回的是最终位置，而不是折叠前的临时位置。原生锚定若已经自己补过，锚点路径的两次测量位置相同、`delta` 为 0；回退路径读到的也是原生锚定完成后的滚动位置。补偿因此可以和浏览器的锚定共存，不需要检测浏览器是否支持 `overflow-anchor`。

## 跳过条件

| 条件 | 行为 | 原因 |
| --- | --- | --- |
| 读者跟底（`[data-chat-following-tail]`） | 不补 | 上游要把视口钉在底部；补阅读位置会把读者拉离底部。 |
| 动画折叠（`[data-chat-motion]`） | 不补 | 「下次有新消息时」的折叠由 ui-chat `foldDriver` 在动画时钟上补偿；再补一次会写两遍。 |
| 没有 `[data-conversation-scroll]` | 不装观察 | 只支持共享滚动口；列表自己滚的布局没有可安全写入的滚动目标。 |
| 隐藏元素不在 `[data-chat-flow]` 列内 | 忽略 | 输入区、菜单等处的 `hidden` 与流程折叠无关。 |
| 隐藏元素自身/后代/祖先都没有锚点键 | 忽略 | 没有可重测的参照物，补偿无法记账。 |
| 阅读线上没有可用锚点 | 回退到最后一条用户消息 | 把消息顶边对到阅读线，给读者一个确定落点；没有用户消息时才不写。 |
| 首条幸存锚点完全落在视口下方（视口被本批占满） | 回退到最后一条用户消息 | 钉住视口外的行会把视口往回滚一整段折叠高度；最后一条用户消息是稳定的回退落点。 |
| 没有可用的用户消息（缺失、隐藏或高度为 0） | 本次不写 | 没有确定性回退落点，不猜位置。 |
| 锚点被隐藏、卸载或清空 | 本次不写 | 锚点路径的 `measure()` 返回 `null` 时补偿放弃，不再改走回退。 |
| 展开（移除 `hidden`） | 不补 | 只认「从无到有」的 `hidden`；展开会改变内容高度，不是折叠。 |

## 边界与失败模式

- **滚动位置在 0（顶部）**：上方内容被收起时没有负空间可回写，浏览器会夹取 `scrollTop`，只能部分补偿或完全不补。这是滚动范围本身的边界。
- **视口被折叠段占满**：回退到最后一条用户消息，把它的顶边对到阅读线；没有可用用户消息时才不写，此时由下方内容按浏览器自己的滚动范围夹取进入视口。
- **React 直接卸载行**：没有 `hidden` 属性可认，补偿不触发。上游如果改成卸载节点收起，`contract.json` 的 `hidden-until-found` 检查会失败。
- **非共享滚动布局**：没有 `[data-conversation-scroll]` 时不安装任何观察；上游换布局后由契约检查提示。
- **动态挂载的滚动口**：运行期用 `childList` 观察文档子树，按 500ms 限频重扫；已经断开的滚动口及时回收。初始扫描同步执行，插件晚于会话视图挂载时也能接上。
- **批次里有无关元素**：只把落在流程列内且带锚点关系的元素纳入批次；无关 `hidden` 既不显回也不参与测量。
- **原生锚定与补偿同时存在**：第二次测量读的是原生锚定之后的位置，差值为 0 时不写，不会双补。
- **补偿安装失败**：只告警一次，不影响策略投影；`slots` 缺席时策略投影跳过，滚动补偿仍独立尝试安装。
- **插件卸载**：`ctx.effect` 的清理断开 body observer 与所有滚动口观察，不留全局监听。

## 术语速查

| 术语 | 含义 |
| --- | --- |
| 滚动口 | `[data-conversation-scroll]`，承载聊天并真正滚动的元素。 |
| 阅读线 | 滚动口顶边 + 1px，用来选锚点行或对齐回退落点。 |
| 视口 | 滚动口当前可见的内容区域：滚动口顶边到顶边 + `clientHeight`。 |
| 锚点行 | 阅读线上第一条未隐藏、非本批、与视口相交、带 `data-chat-anchor-key` 的流程行。 |
| 回退落点 | 没有可见锚点时使用的最后一条未隐藏用户消息行，顶边对齐阅读线。 |
| 本批元素 | 同一批 `hidden` 属性变化里被隐藏的一组元素。 |
| 原生滚动锚定 | 浏览器自动维持可见内容位置的能力，受 `overflow-anchor` 控制。 |
